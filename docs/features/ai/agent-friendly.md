# Agent-friendly tooling

python-wrap ships tools that help AI coding agents (and people) pick the right API and use
it correctly: an `llms.txt` index, a machine-readable API index, plain-language recipes, a
packaged usage guide, ready-to-copy rule files and a read-only MCP server. All of them are
generated from the docstrings, signatures and docs, so they always match the installed
version, and none needs a dependency.

## llms.txt

The documentation site serves [`llms.txt`](../../llms.txt) (an [llmstxt.org](https://llmstxt.org)
index of every page with a one-line description) and [`llms-full.txt`](../../llms-full.txt)
(the agent guide, the key pages in full and every public signature). Point an agent at
`https://pythonwrap.readthedocs.io/llms.txt`.

Both files are generated by `scripts/gen_llms.py` from `mkdocs.yml` and the docstrings;
`tests/test_llms_txt.py` fails when they are stale.

## The API index

<!-- skip -->
```bash
python -m python_wrap api                      # every public name with its summary
python -m python_wrap api retry                # signature, parameters, raises, example
python -m python_wrap api presets.http_client  # names public in a submodule
python -m python_wrap api CircuitBreaker.reset # methods too
python -m python_wrap api search rate limit per user
python -m python_wrap api --json               # the whole index as JSON
python -m python_wrap api retry --json
```

The same data is available in Python:

```python
from python_wrap.introspect import api_index, get_symbol, search

entry = get_symbol("retry")
assert entry is not None
assert entry.signature.startswith("retry(")
assert any(param.name == "max_attempts" for param in entry.params)
assert search("circuit breaker")[0].name == "circuit_breaker"
assert any(item.qualname == "python_wrap.doctor.explain" for item in api_index())
```

## Recipes: from a need to the API

<!-- skip -->
```bash
python -m python_wrap recipe retry http calls
python -m python_wrap recipe stop duplicate emails
python -m python_wrap recipe limit llm tokens
python -m python_wrap recipe            # list every recipe
```

Each recipe names the APIs, gives a runnable snippet, the pitfalls and the docs page:

```python
from python_wrap.introspect import find_recipes

best = find_recipes("stop duplicate emails")[0]
assert "idempotent" in best.apis
print(best.render())
```

The table lives in `src/python_wrap/_data/recipes.json`. To teach it a new need, add an
entry with `need`, `keywords`, `apis` (names as printed by `python -m python_wrap api`), an
optional runnable `snippet` and `notes`, and the `docs` path. `tests/test_introspect.py`
checks that every API exists and runs every snippet.

## The agent guide

`python -m python_wrap guide` prints a short guide to using python-wrap correctly: layer
order, idempotency rules, what never to retry, common mistakes and doctor usage. It is a
file inside the wheel (`python_wrap/_data/agent_guide.md`), so it matches the installed
version and works offline.

## The MCP server

`python -m python_wrap mcp` is a [Model Context Protocol](https://modelcontextprotocol.io)
server over stdio (JSON-RPC 2.0, one message per line), written with the standard library
only. Its tools are all read-only:

| Tool | Arguments | Returns |
| --- | --- | --- |
| `explain_policy` | `import_path` | layers outermost first, canonical order, findings |
| `doctor` | `import_path`, `idempotent=true`, `multiprocess=false` | `ok`, layers, findings (PW001-PW019) |
| `migrate_preview` | `source`, `filename` | unified diff of the tenacity/backoff codemod, notes; never writes |
| `search_api` | `query`, `limit=10` | matching names with signatures and summaries |
| `get_symbol` | `name` | signature, parameters, raises, example |
| `recipe` | `need`, `limit=3` | recipes with APIs, snippet, pitfalls |
| `guide` | | the agent guide |

`import_path` is `package.module:attribute`, for example `myapp.clients:users_policy`.

### Project configuration file

Most MCP clients read a project-level `.mcp.json`:

<!-- skip -->
```json
{
  "mcpServers": {
    "python-wrap": {
      "command": "python",
      "args": ["-m", "python_wrap", "mcp", "--allow", "myapp"]
    }
  }
}
```

Use the interpreter of your project's virtual environment (for example
`.venv/bin/python`, or `"command": "uv", "args": ["run", "python", "-m", "python_wrap", "mcp"]`)
so the server can import your code.

### Editor configuration

The same entry in your editor's own `mcp.json`:

<!-- skip -->
```json
{
  "mcpServers": {
    "python-wrap": {
      "command": ".venv/bin/python",
      "args": ["-m", "python_wrap", "mcp", "--allow", "myapp"]
    }
  }
}
```

### Any MCP client

Run `python -m python_wrap mcp` as a stdio server from the project directory. The server
supports protocol revisions `2025-11-25`, `2025-06-18`, `2025-03-26` and `2024-11-05`
and handles `initialize`, `notifications/initialized`, `ping`, `tools/list` and
`tools/call`. [`examples/mcp_client_demo.py`](https://github.com/LitePy/PythonWrap/blob/main/examples/mcp_client_demo.py)
is a complete client in 60 lines of standard library code.

In-process, for tests:

```python
from python_wrap.mcp import Server

server = Server()
reply = server.handle({
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {"name": "recipe", "arguments": {"need": "retry http calls"}},
})
assert reply is not None and reply["result"]["isError"] is False
assert reply["result"]["structuredContent"]["recipes"]
```

### Security

The server never writes files, opens network connections, starts processes or calls the
code it inspects. It does **import** the module named in `import_path`, which runs that
module's top-level code, exactly like `python -m python_wrap doctor`. Run it only in an
environment whose code you trust, and pass `--allow PREFIX` (repeatable) to restrict
imports to your own packages. Output printed during an import goes to stderr. See the
[threat model](../../project/threat-model.md#agent-tooling-and-the-mcp-server).
